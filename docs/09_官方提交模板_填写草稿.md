## 2、摘要（300 字以内）

PhyWear 把"手机物理实验"搬到腕上：在立创·黄山派（SF32LB52，390×450 AMOLED）上，用 LVGL 9.1 +
openvela 从零实现 16 个物理实验/测量页面（单摆测 g、弹簧振子、向心力、倾角、磁力计数、三类频谱、
秒表、光/声快门、掌声计、音频发生器等），并集成 openvelaClaw（`packages/ai_agent`）：新增 4 个
PhyWear 工具、1 个自定义 Skill（开机自动装到 `/data/agent/skills/`）、手表端「AI 教练」页
（端侧 Agent 状态 + 回执 + 4 个快捷请求）。实测：真机启动 5/5 正常、渲染 41 FPS（EPIC 硬件加速）、
麦克风可测到 −8 dBFS 声学闭环、7 分钟泡机 0 复位；LLM 后端（小米 MiMo Token Plan）在模拟器实测
`llm=ok` 并由模型自主发起 4 次工具调用。已修复 7 个真机问题（含中文内容 UTF-8 截断致云端 400、
跨任务 fd 读传感器失败）。本板没有无线网卡（WiFi 不可达，`ifconfig` 直接 ENOENT；网络已改由 **PPP over BLE** 承载并实测打通）、③ 姿态精度无转台真值等限制均如实标注；**蓝牙阶段 A + 阶段 B 的 B1/B2 已打通并真机实测**（`bt_enable rc=0` + GATT 服务 + 可发现广播 + 服务端自检 PASS），**仅「真手机点一次」未做**（宿主 BlueZ 已验证同一套 ATT 动作）；主动场景已交付并真机验证。

## 3.1 绪论

**应用场景与痛点**：中学/大学物理实验中，"单摆测 g、弹簧振子、向心力"等需要秒表、刻度尺、
测力计等器材，误差大、记录繁琐；手机 phyphox 类应用虽好，但"手里拿着手机晃"既不方便也不符合
实验场景。腕上设备天然贴合"摆动/倾角/加速度"这类被测对象，且传感器随手表佩戴。

**技术难点**：① 新硬件平台从零适配（显示/触控/传感器/音频驱动与 openvela 集成）；
② 在 512 KB SRAM（静态占用 93%）与无 FPU 预算下保证 40+ FPS 的实时曲线；
③ 端侧 AI Agent 与 GUI 线程共存（LVGL 非线程安全、NuttX fd 属任务组）；
④ 端云链路的中文编码兼容与无网络降级。

**创新点**：腕上形态的物理实验（区别于手机 app）；自研 `pw_scope`/`pw_graph` 走 EPIC 硬件
加速的曲线控件；"能主动、会执行"的 Agent 集成（4 工具 + Skill + 手表端 AI 面板）；
端侧离线意图表保证断网可用。

## 3.2 系统方案设计

**总体架构**（框图见 `docs/figures/`）：应用层（PhyWear LVGL 应用 + 16 页面）→ 桥接层
（`pw_ai.c` 线程安全邮箱：Agent 只投递"打开某页"，所有 LVGL 调用都在 GUI 线程）→
Agent 层（`packages/ai_agent`：Router/Tool/Skill/cron/心跳）→ 系统层（openvela/NuttX + SiFli BSP）。
传感器与音频经 NuttX 字符设备（`/dev/lsm6dsl0`、`/dev/mag0`、`/dev/light0`、`/dev/mic0`、`/dev/spk0`）。

**选型与职责划分**：开发板选黄山派（官方赛道硬件、AMOLED + 丰富传感器 + 音频编解码）；
端侧负责采集、实时绘图、离线意图与工具执行；云侧（LLM）仅负责自然语言理解与讲解。
**断网/弱网降级**：真机无网络栈 → 走 `agent_loop.c` 的离线关键词意图表（13 条）+ 工具直执行，
Agent loop 改为**开机无条件启动**（原生逻辑要等网络连上，真机永远等不到）。

**关键模块**：① `pw_ai` 邮箱（跨线程单向请求）；② `velaclaw` 本地客户端（App→Agent 问答，
支持异步回复）；③ Skill 装载器（`/data/agent/skills/`，开机自动安装）；④ 声学互斥（喇叭与麦克风
共用 AUDCODEC 模拟通路，必须互斥，否则卡死）。

## 3.3 核心算法与技术原理

- **端侧模型**：无（端侧不做推理，使用规则/算法；这避免了"假 AI"）。
- **云端模型**：小米 **MiMo Token Plan**（`token-plan-cn.xiaomimimo.com`，`mimo-v2.5-pro`，
  OpenAI 兼容协议，`api-key`/`Bearer` 均可）；鉴权经设备内 `config_store`（`set_llm` 命令），
  密钥不入库。实测一轮对话 `trace … llm=ok backend=0`，并由模型自主发起 4 次工具调用。
- **姿态解算（③ 惯性标尺）**：**Mahony 显式互补滤波（MARG 9 轴，本队自写实现）** —— 四元数姿态 +
  陀螺零偏显式积分状态，磁力计只修偏航（权重 0.5，默认不进积分以免磁噪声被积进零偏）；
  状态仅 76 B，单帧约 100 flop；**dt 用 `CLOCK_MONOTONIC` 实测量**，不用固定标称值。
- **标定数学（③）**：**六面法**加速度零偏/刻度（真值 = 重力）、**磁椭球拟合**（硬铁 + 软铁，
  9 参数代数拟合 + Jacobi 特征分解）、**陀螺静态零偏**（含「够不够静」判据）。全部用**流式充分统计**，
  不保存原始样本 —— 磁椭球只占一个 9×9 正规方程（360 B），标定开销与采样点数无关。
- **关键机制**：FFT（radix-2 迭代 Cooley-Tukey，复用于三类频谱）、自相关测周期（单摆/弹簧）、
  向心加速度过原点最小二乘（a–ω² 斜率求半径）、阈值滞回事件对（光/声快门与掌声计）、
  传感器融合（合模长判摆动）。
- **openvela 能力运用**：**图形**（LVGL 9.1 + SiFli EPIC 硬件加速，官方 PR #31/#41/#121，
  非本队原创）、**AI**（openvelaClaw Agent 框架、工具注册、Skill 机制、cron 心跳）、
  **多媒体**（AUDCODEC 采集/播放）。本队对 openvela 的拓展：PhyWear 工具与 Skill 沉淀、
  `skill_loader` 的 UTF-8 边界修复（避免中文 Skill 触发云端 400，**可回流上游**）。

## 3.4 系统实现

- **软件/固件架构**（2026-09-18 更新：含 zblue 蓝牙 host 栈的出货构建，本机构建产物 **2554008 B**；flash 占用随构建变动，以 `docs/evidence/bt-b3-20260918/` 与 `docs/16 §12` 的口径为准）：`app/phywear/`（**50 个手写源文件 / 19,144 行**，另有 5 个生成的 CJK 字体文件，
  572 码点）；真机固件 **2.20 MB / 16 MB flash（13.14%）**，SRAM **487,460 B / 512 KB（92.98%）**。
- **数据流**：传感器字符设备 → 采样线程/主循环 → 曲线控件（`pw_scope`，354×96 RGB565 软光栅
  → `lv_image` → EPIC blit）→ 屏幕；Agent 侧只经邮箱请求切页，不直接触碰 LVGL。
- **硬件适配（是）**：芯片/板型 **SiFli SF32LB52 / 立创·黄山派 SF32LB52-MOD-1-N16R8**；
  驱动类型：显示（co5300 AMOLED + EPIC）、触控（FT6146）、传感器（LSM6DSL、MMC5603、LTR303）、
  音频（AUDCODEC DAC0/ADC0）；适配难点与解决：触控在 EPIC 栈上失效（本队修复）、
  启动偶发卡死（时钟/晶振建立时序补 2 ms 等待）、麦克风增益过低（`MIC_VOLUME 30`）、
  喇叭换频爆音（音量爬坡淡入淡出）。
- **应用/交互端**：LVGL 全中文界面（i18n 双表 **267** 条/语言 + CJK 子集字体），
  主菜单 8 板块（自绘图标）、**16 个主页面** + 原始传感器 6 子页 + **「水平仪」4 子页**
  （实时数值/零偏标定/重力标定六面/磁标定，无头入口 `cap imu*`；主页 tile 待板块落位）；
  手表端「AI 教练」页展示 Agent 状态与最近回执。
- **自定义 Skill（硬性要求）**：`app/phywear/skills/phywear-physics-coach.md`（5,165 B，
  含**触发场景 / 操作步骤 / 输出规范**三要素），开机自动安装到 `/data/agent/skills/`；
  触发场景：用户问"能做哪些实验/帮我测重力/这个数据什么意思"时，Agent 按 Skill 调 4 个工具
  （`phywear_list_experiments` / `phywear_open_screen` / `phywear_read_sensor` / `phywear_run_experiment`）。

**未达预期/受限项**：③ 姿态**精度指标尚无转台真值**（只有与加速度计一致性证据），磁软铁只能定到一个未知旋转；主动场景残余——静止/振动桌面下单摆页仍可能给出无效 g（三道有效性门有漏过，约 1 条/70 s）；**蓝牙（2026-09-18 更新）**：**B1/B2/B3 全部打通并真机实测**。阶段 B 两个真根因：**①NuttX 的 fd 表按 `task_group` 存放**，而 zblue port 把 HCI 命令的 `write()` 放在 Zephyr 系统工作队列线程里 ⇒ 与 `h4_open()` 不同组 ⇒ 恒 `EBADF`，控制器一个字节都没收到（`-EIO` 是 `hci_cmd_done(..UNSPECIFIED)` 伪造 status 的假象）；修法：`h4_send()` 只入队、`write()` 交给同组的 `h4_rx_thread`。**②`gatt_notify_mc()` 漏 `data.handle = handle;`** ⇒ 通知帧 value handle 恒为 **0x0000** 被 BlueZ 静默丢弃（设备侧 56 条 `notify rc=0` 全绿、宿主 0 包 —— 「发出去了」不等于「对端收到了」）；修法：补该行。修复后通知帧句柄 **0x0010**、宿主正常收包。**B3 无人化完成**：宿主自任 BLE 中心，`tools/pw_bt_b3.py --central` 一条命令跑完复位→扫描/连接/读 16 B/订阅/写 `ping` ⇒ **设备 6/6 + 宿主 9/9、退出码 0**。⚠️ **未在真手机（Android/iOS）上点过**（宿主 BlueZ 对应手机 nRF Connect 的同一套动作）；⚠️ 广播用**随机地址** ⇒ 按名字 `PhyWear` 找、不能按 MAC；SRAM 已降到 **85.20%**（把只读符号表 `g_allsyms` 由 `.data` 改 `const` 进 flash，−45,952 B，符号解析保留）；**轨迹页的相对位移尚无真机手推真值**（需人按 `真值测量操作协议.md` 用直尺做，未拿到前不宣称 cm 级精度）；板载喇叭响度受硬件上限（PA 开关与音量 30%→100% 仅差 1–3 dB）；
音频发生器频率按 20 Hz 步进；模拟器 IMU 为合成波形（仅演示链路，**不作测量证据**）。

## 3.7 总结与展望

**成果**：在全新硬件平台（SF32LB52/黄山派）上完成从驱动适配到应用、从 Agent 集成到 Skill 沉淀的
完整闭环，形成 16 页腕上物理实验应用 + 4 个 AI 工具 + 1 个设备端 Skill，并留下可复现的文档、
