## 2. 构建

### 2.1 真机（立创黄山派 SF32LB52，含 AI Agent）

板级配置：`vendor/sifli/boards/sf32lb52/sf32lb52_lchspi_ulp/configs/nsh-ai`
（= 官方 `nsh` 配置 + `CONFIG_EXAMPLES_AI_AGENT_VELA=y` + 声学 `CONFIG_SF32LB52_SPK=y` 等）

```bash
cd ~/openvela

# 首次、或改过 defconfig 之后：删掉 .config 强制按 defconfig 重新生成
rm -f cmake_out/sf32lb52_lchspi_ulp_nsh_ai/.config
cmake -B cmake_out/sf32lb52_lchspi_ulp_nsh_ai -S nuttx -GNinja \
  -DBOARD_CONFIG=../vendor/sifli/boards/sf32lb52/sf32lb52_lchspi_ulp/configs/nsh-ai \
  -DEXTRA_FLAGS="-Wno-cpp -Wno-deprecated-declarations"

# 日常增量编译
cmake --build cmake_out/sf32lb52_lchspi_ulp_nsh_ai -j16
```

产物：`cmake_out/sf32lb52_lchspi_ulp_nsh_ai/nuttx.bin`（约 **2.03 MB / flash 12%**，SRAM 约 488 KB / 93%）。
构建末尾会打印 `Memory region … flash/sram/psram` 三段占用，**SRAM 一旦 100% 会直接链接失败**（不是运行时问题）。

> ⚠️ **不要全局打开 `CONFIG_DEBUG_ASSERTIONS`**：本板会在 `HAL_Init()` 之前触发断言并卡在启动阶段。
> 需要看断言/崩溃输出时，只临时打开 `CONFIG_SYSLOG_CONSOLE=y`。

## 3. 烧录（真机）

```bash
cd ~/openvela
./flash_with_ftab.sh cmake_out/sf32lb52_lchspi_ulp_nsh_ai/nuttx.bin /dev/ttyUSB0
#   等价于：sftool 先写 ftab -> 0x12000000，再写固件 -> 0x12010000，最后读回校验
#   换 ftab：FTAB=/path/to/ftab.bin ./flash_with_ftab.sh <bin> /dev/ttyUSB0
```

要点（都是踩过的坑）：

- **顺序不能反**：ROM 先读 flash 起始 `0x12000000` 的 ftab（FlashTable），才知道二级引导在哪。
  出厂该区域是空的 —— 只烧固件不写 ftab 会一直只打印 `SFBL`。
- 启动判据：`SFBL` → **`ABCD`** → `ADC calibration…` → `NuttShell (NSH)` / `nsh>`。
  只看到 `SFBL` 没有 `ABCD` ⇒ ftab 没写进去（**不是硬件坏**，sftool 通常仍能秒连）。
- **禁止 `erase_flash`**（擦不擦都不会凭空产生 ftab，只会让排查更乱）。
- 读回校验报 **"固件 ❌ 不一致" 多数是 sftool 的已知抖动**：重试几次，或分块读回复核：

```bash
# 分块读回逐字节比对（失败重试 5 次；注意最后一块长度要按文件剩余长度算）
sftool -c SF32LB52 -p /dev/ttyUSB0 -b 1000000 --before default_reset --after no_reset \
       read_flash /tmp/rb.bin@0x12010000:16384
dd if=cmake_out/sf32lb52_lchspi_ulp_nsh_ai/nuttx.bin of=/tmp/src.bin bs=1 count=16384
cmp /tmp/rb.bin /tmp/src.bin && echo OK
```

- **动效查表与 Skill blob 的生成物纪律（2026-09-16）**：三个文件是**生成物**，改完源必须重跑脚本，
  否则会出现"代码改了、固件里还是旧的"：

  ```bash
  python3 tools/phywear/gen_motion_table.py --check   # 动效曲线表 pw_motion_table.c（改曲线才需要重跑）
  python3 tools/phywear/gen_skill_blob.py             # skills/*.md → pw_skill_blob.c（**加/改 Skill 必跑**）
  python3 tools/phywear/gen_skill_blob.py --check     # 校验是否过期（提交前跑）
  ```

  动效计时口径：主机 `pw_math_hosttest --bench`；真机 `phywear motionbench 20000`（打印两条实现的 ns/次与倍数）。

- **蓝牙阶段 A（2026-09-16）：改 defconfig 后必须重新 configure**：只改板级 defconfig 文件而直接
  `cmake --build` **不会生效**（产物尺寸一模一样），必须先删 `.config` 再 configure：

  ```bash
  rm -f cmake_out/sf32lb52_lchspi_ulp_nsh_ai/.config
  cmake -B cmake_out/sf32lb52_lchspi_ulp_nsh_ai -S nuttx -GNinja \
    -DBOARD_CONFIG=../vendor/sifli/boards/sf32lb52/sf32lb52_lchspi_ulp/configs/nsh-ai \
    -DEXTRA_FLAGS="-Wno-cpp -Wno-deprecated-declarations"
  cmake --build cmake_out/sf32lb52_lchspi_ulp_nsh_ai -j16
  ```

  阶段 A 的三处改动与回退（`docs/03 §4.10`）：① defconfig 的 `CONFIG_UART_BTH4=y`（改回 `# … is not set` 即回退）；
  ② `external/zblue/CMakeLists.default.txt` 里 `if(CONFIG_BT_H4)` 两行；③ 新增 `.../hci/bt_snoop_stub.c`。
  **注意 defconfig 里只能写裸 `CONFIG_*=y` 行**：带引号/全角括号的自由注释会让 CMake 列表解析报
  `string sub-command REGEX … needs at least 5 arguments`（踩过，说明写进本文件与 `docs/03`）。

- **一条命令 = 一次 GUI（2026-09-15 踩坑）**：`phywear lang zh` **本身就会启动 GUI**，
  所以"设中文 + 打开某页"必须写成**一条命令**：

  ```bash
  phywear lang zh cap imutraj          # 设中文并停在轨迹页（无头截图用同一写法）
  phywear lang zh cap imutrajbench --shot=9000   # 等 9 s 再流式吐一帧（--shot=<ms> 是延时）
  phywear lang zh shot imutraj         # 取一帧就退出（pwshot.py shot 用的就是这条）
  ```

  分两条发就是**两次 GUI**：第二个实例会卡在 LCD 驱动里（`CONFIG_TTY_SIGINT` 关着，Ctrl-C 也杀不掉），
  现象是心跳只剩 root 屏的 `fps=3`、看不到目标页的串口输出。此时**复位重来**，不要再发命令。

- **真机精度类验证靠串口读数**：轨迹页每 0.5 s 打一行 `[TRAJ] t=.. x=.. y=.. z=.. v=.. still=.. |a|=.. |w|=.. bad=.. bias=..`，
  内容与屏幕一致；`phywear cap <page>` 前台跑时直接读串口即可（真机没有 `/dev/fb0`，拍照不是唯一途径）。

- **`restore_code.py` 之后必须先 `touch` 再编译（2026-09-15 踩坑）**：恢复快照会**保留快照里的
  mtime**；若它比构建目录里的 `.o` 旧，ninja 认为"无需重编"而**跳过**，于是烧出混合固件
  （本次现象：倾角页有新的指针盘、原始传感器页却还是旧版式）。判据与修法：

  ```bash
  # 判据：目标文件里应当出现新符号；为 0 就是没重编
  nm cmake_out/sf32lb52_lchspi_ulp_nsh_ai/apps/examples/phywear/CMakeFiles/apps_phywear.dir/phywear_raw.c.o \
     | grep -c pw_scope_set_lanes_i16
  # 修法
  touch apps/examples/phywear/*.c apps/examples/phywear/*.h && <重新构建>
  ```
- 若板子长时间卡在启动：**先复位**；仍不行再重新烧 ftab + 固件。
- **读窗口取 16 KB**：2026-09-15 实测 64 KB / 256 KB 的单次 `read_flash` 会在 ~90% 处
  `timeout while waiting for reading flash`（读得越远越慢），而 16 KB 稳定；
  2 MB 全片逐个 16 KB 太慢，建议**按 16 KB 采样若干偏移**（首块 + 256 K/512 K/1 M/1.5 M + 末块）。
- 参考口径（2026-09-15 最后一次烧录已验证）：真机固件 `md5 c6bf6e688b34c8da162788acf61d8a92`，
  `2,064,640 B`（UI 第二批 (a)(b)(c) + 三轴页双视图修订）。
  重新编译后 md5 必然变化，请以自己构建的产物为准；上一版 `484b64ca2e9cd157a191f8ea7d022f9a`
  （2,057,968 B）留档于 `~/桌面/PhyWear-rollback-20260915-0002/firmware/nuttx.bin`。
- **惯性标尺 UI 的无头入口（2026-09-15）**：`phywear cap imu`（实时数值）、
  `imubias`（零偏标定）、`imu6`（重力标定/六面）、`imumag`（磁标定）；
  模拟器可用 `phywear tap <x> <y>` 真按按钮（按键中心：零偏页 (105,164)、六面页 (115,208)）。
  测堆：`python3 docs/evidence/imu-ui-20260915/repro-heap.py {root|imu}`。

## 4. 串口与安全铁律

- 串口参数：`/dev/ttyUSB0`，**1 000 000 8N1**；CH340N 的 **RTS 直连 SoC 复位（低有效）**。
- **铁律 1**：`pyserial` 打开串口后必须立刻释放调制解调器控制线，否则板子被按在复位上：

```python
import serial
p = serial.Serial('/dev/ttyUSB0', 1000000, timeout=0.2)
p.dtr = False
p.rts = False          # 立刻释放；想主动复位再 p.rts=True -> sleep(0.2) -> False
```

- **铁律 2**：`picocom` 必须带这两个参数，否则同样会把板子按住：

```bash
picocom -b 1000000 --noreset --lower-rts --lower-dtr /dev/ttyUSB0     # 退出：Ctrl-A 然后 Ctrl-X
```

- **铁律 3**：`/dev/ttyUSB0` 独占 —— `picocom` 与脚本不能同时打开（会报
  `device reports readiness to read but returned no data`）。
- **铁律 4**：打开串口/复位都会让板子重启（RTS 接复位），属正常现象，不要当故障。
- 本机现成工具（推荐，省得自己写 pyserial）：

```bash
python3 ~/openvela/tools/phywear/boardsh.py --run "phywear micread 10" --wait 4
python3 ~/openvela/tools/phywear/boardsh.py --reset --run "ls /data"      # 需要冷启动时
```

## 5. 真机自检清单（当前固件，逐条可跑）

### 5.0 先跑自动验收（**推荐从这里开始**）

```bash
cd ~/openvela
python3 tools/phywear/pw_accept.py --out docs/evidence/accept-$(date +%Y%m%d-%H%M)
```

一条命令跑完**设备侧 18 项**（不需要手机）：阶段 A 裸探针 → B1 `bt_enable rc=0` →
B2 GATT/广播 → 服务端自检（属性表 / 句柄结构 / 采样耗时 / 通知链演练）→ 帧率 →
主页截图（与金标 sha256 比对）→ 浸泡。逐项打 PASS/FAIL 并落盘 sha256
（`--skip-soak` / `--skip-shot` 可裁剪）。**2026-09-18 实测 18/18 全过。**

蓝牙 B3（手机连接读写）另有一条需要真手机的命令：

```bash
python3 tools/pw_bt_b3.py --selftest                       # 先验判定器本身（5/5，不碰板子）
python3 tools/pw_bt_b3.py --out docs/evidence/bt-b3-$(date +%Y%m%d-%H%M) --wait 240
# 手机上：按**名字**找 "PhyWear"（广播是随机地址，别按 MAC）→ 连接 →
#         读 …a001（handle 0x0010）→ 打开 Notify → 往 …a002（handle 0x0013）写 ping
```

⚠️ 跑帧率时注意口径：`fps = 本窗口推屏数 / 30`，窗口从 GUI 启动算 ——
**命令发出时刻不同读数会不同**（实测 t≈3 s 发是 204/12，t≈6 s 发是 183/11）。
`pw_accept.py` 已固定为 0.5 s 同口径。

### 5.0b USB-SLIP 网络通路（任务 3 的替代路径；本板无 WiFi 网卡）

本板（黄山派 SF32LB52）**没有无线网卡**：`ifconfig` 直接 `ifconfig: open failed: 2`（ENOENT），
所以 ai_agent 的 `set_wifi <ssid> <pass>`（走 `ifup wlan0` + `wapi`）**在这块板上不可达**。
但"拿到 IP + 把测量数据发到宿主"本身能做，换一条**不需要网卡**的链路即可：
**SoC USB 设备口 → CDC-ACM → SLIP**。三层前提都已具备：

| 层 | 事实 |
|---|---|
| 引脚 | `bsp_pinmux.c:178-179` 把 `PAD_PA35/36` 配成 **USB_DP/USB_DM** |
| 板级 | `sifli_ap.c:693` 已 `cdcacm_initialize(0, NULL)`，板上 `/dev/ttyACM0` 存在 |
| 驱动 | `CONFIG_SF32LB52_USBDEV=y`（控制器驱动已编入）+ `CONFIG_NET_SLIP=y`（本轮新开） |

**板子侧**（一条命令）：
```bash
phywear net        # = slip_initialize(0, "/dev/ttyACM0")
# 期望： [net] slip_initialize rc=0 (sl0 已注册)
ifconfig           # 应出现 sl0
ifconfig sl0 192.168.7.2      # 先静态验证 IP 层
```

**宿主侧**（对端）：
```bash
lsusb | grep 38f4              # 插线后应看到 38f4:a4a7 "CDC/ACM Serial"
ls /dev/ttyACM*                # generic cdc_acm 驱动会自动建，无需 udev 规则

# ⚠️ 前置检查：slattach/ifconfig 在 net-tools 包里，**本机当前没装**
#    （2026-09-18 实测：which slattach → 未找到；dpkg -l net-tools → 空）
which slattach || sudo apt install -y net-tools

sudo slattach -p slip -s 115200 /dev/ttyACM0 &
sudo ifconfig sl0 192.168.7.1 pointopoint 192.168.7.2 up
ping 192.168.7.2               # 通了 ⇒ N2（端到端通路）成立
```

> **替代方案（不想装 net-tools 时）**：本机已有 `pppd`（PPP，标准工具，通过 IPCP 自动分配地址
> —— 那正是"拿到 IP"这件事）。走 PPP 需要板子侧另开
> `CONFIG_NETUTILS_PPPD=y`（它会 `select NETUTILS_CHAT` + `NET_TUN`）并写 chat 脚本，
> 也就是把复杂度从宿主搬到板子。**两条路都没实测过**（都卡在同一根 USB 线上），
> 选哪条见 `docs/16 §11.3` 的记录。

**要走 DHCP（N1）**：宿主起 `dhcpd`/`dnsmasq` 给 `sl0` 发租约，板子执行 NSH 的
`renew sl0`（已开 `CONFIG_NETUTILS_DHCPC=y`）。

⚠️ **现状如实说明**：软件侧已就绪并实测过失败路径 —— `phywear net` 目前回
**`rc=-107`（= -ENOTCONN）**，根因已定位到行：`slip_initialize()` 只在 `file_open()`
失败时返回错，而 `/dev/ttyACM0` 被 cdcacm 拒 —— `nuttx/drivers/usbdev/cdcacm.c:2140`
`if (priv->config == CDCACM_CONFIGIDNONE) return -ENOTCONN;`（注释即 `SETUPNOTCONNECTED`）。
**⇒ 板的 USB 设备口没有被任何主机枚举，只差一根 USB 数据线。**
看到 `-107` 就是"线没插"，不是软件问题；插上后该行应变成 `rc=0`。

## 6. 常见坑（按踩坑频率排序）

| # | 现象 | 原因 / 处理 |
|---|---|---|
| 1 | 同一次开机里跑第二个 `phywear`（GUI）会挂在 LCD 驱动 | 一个 boot 只跑一个 GUI 实例：**先复位再跑**。文本子命令（`tone`/`micread`）不受影响 |
| 2 | 进 GUI 后 Ctrl-C 杀不掉 `phywear` | 固件未开 `CONFIG_TTY_SIGINT`：**只能复位**（重开串口即复位） |
| 3 | 串口读报 `multiple access on port` | `/dev/ttyUSB0` 被 `picocom` 或另一个脚本占用，先释放 |
| 4 | Agent 启动后报 `No API key` / `Network timeout` | 真机无网络栈（无 WiFi/以太网驱动），属预期；端侧关键词直通与 4 个工具仍可用。`/data/agent` 目录由 Agent/PhyWear 自行创建 |
| 5 | 构建报 `aidl: not found` / `mcopy: not found` / `undefined reference to get_disp_buf` | PATH 没带上 §1 的三个目录；`get_disp_buf` 是**只有真机 LCD 驱动才有**的符号，模拟器下 `pw_shot.c` 已退化为桩 |
| 6 | 中文界面出现缺字方框 | CJK 字体子集没覆盖新文案：跑 `bash ~/openvela/tools/phywear/gen_fonts.sh` 重生成 5 个字号后重编 |
| 7 | 模拟器启动失败并报 “Running multiple emulators with the same AVD” | 上次的 qemu 还活着：`pkill -f "[q]emu-system-aarch64"`（注意用方括号写法，避免匹配到自己的命令行） |
| 8 | 真机启动只打印 `AB` / `ABCD` 后无输出 | 已修（`BSP_Board_PreInit` 时钟/晶振建立时序：XTAL32、DLL1、DLL2 各加 2 ms 等待）。若再现，先按 §3 重烧，再看 `[phywear] alive` 心跳判断 GUI 是否存活 |
| 9 | 改了 `defconfig` 但 `cmake --build` 后配置没变 | Kconfig **不会**自动重跑。必须 `cmake --build <build目录> --target resetconfig` 再 `cmake --build`（2026-09-18 踩过，白编译一轮） |
| 10 | 手改 `cmake_out/…/.config` 后 configure 失败：`nuttx_export_kconfig(): string(REGEX MATCH) needs at least 5 arguments` | 手改 `.config`（例如删空行）会带坏 `process_config.py` 链路。**改配置只走 `defconfig` + `resetconfig`**（我为此白查一轮） |
| 11 | 串口发命令只回显、不执行 | 本板控制台行结束符是 **`\n`**，不是 `\r`。（`pwshot.py` 能用是因为它发 `\r\n`） |
| 12 | 命令偶尔被回 `Unknown command: …` / `nsh: …: command not found` | NSH 与 ai_agent 的 `vela>` CLI **抢同一个 stdin**，谁先阻塞在 read 谁拿到那行。固定脚本里要**发完确认生效再继续**（`pw_bt_b3.py` 已是这么做的） |
| 13 | 帧率对不上（例如 11 vs 12） | `fps = 本窗口推屏帧数 / 30`，窗口从 GUI 启动算 ⇒ **命令发出时刻不同读数不同**（实测 t≈3 s 发 204/12、t≈6 s 发 183/11）。比帧率必须固定发出时刻 |
| 14 | `phywear cap bt` 之后打不开别的 GUI 页 | 它会把 GUI 一起带起来（`pw_cap_open("bt")` 只做 BT 初始化，但 `main()` 继续进 LVGL 主循环），root 页 `fps=3` 属正常区间（3~7）。**这个 boot 的 GUI 额度被它用掉了** |
| 16 | `phywear net` 回 `rc=-107` | `-107=-ENOTCONN` = USB 设备口没被宿主枚举（`cdcacm.c:2140`）。**插 USB 数据线**即可；宿主应出现 `38f4:a4a7` 与 `/dev/ttyACM*`。详见 §5.0b |
| 15 | 蓝牙失败时串口**一个字都没有** | 本板默认没开 `CONFIG_BT_DEBUG_LOG`，`port/include/zephyr/logging/log.h` 会把整个 BT 栈的 `LOG_*` 编译成空语句。排障第一件事就是把 `CONFIG_BT_DEBUG_LOG=y` + `=4` 加回去（改完记得 `resetconfig`）；需要 H4 字节级日志再把 `h4.c` 的 `PW_H4_TRACE` 置 1 |
