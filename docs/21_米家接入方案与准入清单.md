# 21 · 米家（Mi Home）接入方案与准入清单

> 写作时间：2026-11-04　｜　作者：DSH 原体（AI 辅助，MiMo 只做文本）
> 一句话结论：**MIoT 蓝牙广播协议层已实现并可被手机扫到；"出现在米家 App 里"取决于小米平台的产品注册与认证，不属于写代码能单方面完成的部分。**

帧格式（全部小端）：

外层是 AD 结构 `0x16`（Service Data）+ UUID `0xFE95`（小端 `95 FE`）。

## 2. 为什么"能广播"不等于"能进米家"

米家 App 添加设备时，是拿广播里的 **Product ID** 去**小米云端产品库**查：
查不到、或该产品未通过认证，就不会出现在可选列表里；绑定环节还要小米账号 + 云端鉴权。
所以产品 ID 不是随便填的数字，而是**平台创建产品后分配的**。

## 3. 三条路与结论

| 路径 | 前提 | 周期 | 结论 |
|---|---|---|---|
| **P1 米家 BLE 直连（官方）** | 个人认证 → 企业开发组（营业执照）→ 创建产品（蓝牙 / 硬件直连；流程含"选模组型号"）→ MIoT 协议实现 → 米家插件 + 卡片 + 测试报告 → 送测认证 → 上架 | 4–8 周 | **唯一"真进米家"的路**；赛期内只能做到"协议层 + 待认证" |
| **P2 Matter（米家当 controller）** | CSA 认证 + DCL 注册 + Wi-Fi/Thread 传输 | — | **不采用**：本板无 Wi-Fi/Thread；SRAM 已用 92.19%，跑不动 CHIP 栈 |
| **P3 局域网互通（miIO / Home Assistant）** | 设备有 IP（PPP over BLE 已通，PAN 在接） | 1 周 | **可做但改名**：能被第三方工具识别，米家 App 不认，不能称"接入米家" |

## 4. 准入清单（若团队决定正式申报）

- [ ] 小米账号 + **个人实名认证**
- [ ] **企业开发组**：营业执照、企业背景、团队经验、申请人信息（审核通过后才能建产品）
- [ ] 创建产品：产品名 / 开发组 / 产品类型 / 型号 / 操作系统（RTOS）/ 联网方式（蓝牙）/ 接入类型（硬件直连）/ **模组型号**
- [ ] 确认是否**必须使用小米认证模组**（流程里有这一项；若强制，自研板路线需另议）
- [ ] MIoT 协议实现：广播（本文档已完成）+ GATT 配网/绑定 + 属性读写 + 事件上报
- [ ] 米家扩展程序（插件）：控制页、卡片、消息推送、隐私协议、帮助与 FAQ
- [ ] 测试报告：功能 / 兼容性 / 稳定性 / 功耗；产品说明书
- [ ] 送审 → 认证 → 上架

## 7. 红线

1. **不冒充已知产品的 Product ID**（例如伪装成温湿度计）——会被显示成别的设备，违规，且答辩一问即穿。
2. 材料里**不写"已接入米家"**，只写"协议层已实现，产品注册与认证待平台审核"。
