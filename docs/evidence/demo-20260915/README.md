## 1. 为什么这里没有视频文件

我实测了三条"自动录屏"的路，**都不可用**：

| 尝试 | 结果 |
|---|---|
| 真机取帧 | 串口 dump 一帧 390×450 RGB565 要数秒 → 只能出静帧（现有 26 张真机截图就是这么来的），做不了动态 |
| 模拟器逐帧录屏 | `adb pull /dev/fb0`（1280×800×4 双缓冲 = 8.2 MB）实测 **0.3 帧/秒**（3.7 s/帧） |
| 模拟器自带录制 | `adb emu screenrecord start/stop` **不生成文件**（本镜像是定制 NuttX，不是 Android UI） |
| 主机转码 | **本机没有 ffmpeg**（`which ffmpeg` 为空），也没有 gst/avconv |

**结论**：真机没有视频输出、模拟器取帧太慢、编码器缺失 → **动态画面只能由人用手机拍 AMOLED 屏**。
所以本目录交付的是"**拍之前要准备的东西**"，而不是片子本身。

## 3. 实拍前请先确认（需要人手上的动作）

| # | 动作 | 为什么机器替不了 |
|---|---|---|
| 1 | **晃手表 3 秒以上**，看是否自动跑单摆并弹出 `AI: 已自动测重力加速度: g = 9.xx` | 摆动检测读的是真实 IMU，机器没法替 |
| 2 | 手转手表，看 `phywear ahrs 20` 的 roll/pitch/yaw 是否跟着变 | 同上 |
| 3 | 三轴页**用手指轻点**切换视图 | 真机没有触摸注入（`/dev/utouch` 只在模拟器） |
| 4 | 声学段落听响度 | 需人耳判断（板载小喇叭声压有限） |

> 若第 1 条的 g 明显偏离 9.8（例如 4~6 或 15+），说明那次摆动幅度/姿态不合适或页面运动判据没抓住，
> 重摆一次即可；如连续多次都不可信，请把现象告知我 —— 那就是我文档里写的"运动判据需要改"的真实证据。
