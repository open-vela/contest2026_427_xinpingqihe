## 一、录制方案

### A. 真机画面（主素材）

真机没有视频输出，**用手机/相机拍 AMOLED 屏**：

1. 板子固定（手机支架 + 板子立起），避免反光；屏幕亮度 80–100。
2. **一段一个 boot**：同一 boot 内运行第二个 `phywear` GUI 会挂在 LCD 驱动里（实测），录坏就 RTS 复位重来。
3. 触控演示用指尖侧面轻点，避免遮挡画面 —— ①的双视图切换、③的标定向导都要拍"手指真的点了"。
4. 串口控制台**单独录屏**（叠加"真机实测"文字证据）：
   `picocom -b 1000000 --noreset --lower-rts --lower-dtr /dev/ttyUSB0`
5. ⚠️ `ai_agent` **已开机自启**（板级 `etc/init.d/rc.sysinit`），**不需要再手敲 `ai_agent &`**（v3 脚本里的那句已过时）。

### B. 静态证据（插入帧）

- UI 第二批 + 修订：`docs/evidence/ui-batch2-20260915/`（含 `rev-real-raw-num/curve.png`、`rev-real-home.png`）
- 主动场景：`docs/evidence/proactive-20260915/`（真机日志 + 拦截证据）

### C. 性能实测（真机，现场录屏）

```text
lvgldemo benchmark          # 约 90 s，直接录控制台输出
```

> 口径：**念屏幕上出现的数字**。当前固件 PhyWear 自身场景实测 **41 FPS**（render 22 / flush 0）；
> 页面级探针（心跳行 `loops/s=` 与 `fps=`）：原始传感器页 **fps 12 / loops 57**（数值与图线两个视图同值）、
> 倾角 **25**、秒表 **9**、单摆 **8~16（随是否在解算波动）**。

### D. AI / 主动场景（**真机离线即可演示**）

```text
复位即可（Agent 自启）→ 日志：[bus] Message bus initialized → [agent] … → 工具注册
phywear &                     # 起 GUI；日志出现 installed skill /data/agent/skills/…
ls /data/agent/skills         # 展示 phywear-physics-coach.md（自定义 Skill 落盘）
```

**⑤-1 主动场景（本片最重要的新增段落）**，两种拍法：

```text
(A) 真实触发（首选，最有说服力）：手拿着表晃 3 秒以上
    期望：手表 AI 消息日志出现"检测到持续摆动（窗口振幅 x.xx g，持续 2.5 s）"
       → Agent 自动调用 phywear_run_experiment → 单摆页被自动打开
       → 表上出现 "AI: 已自动测重力加速度: g = 9.xx m/s^2 (T = x.xxx s)"
(B) 无头复现（口播/串口镜头用）：phywear coach 检测到持续摆动 请跑单摆实验测重力加速度
```

> ⚠️ **必须如实的两点**（见 §四红线）：① 静止/振动桌面上页面会算出无效 g，
> 我们加了"独立数据 + 可复现 + 合理性(5~15 m/s²)"三道门，**拦不住的那部分如实承认**；
> ② 真机上 Agent 的"解释"走**离线意图**（真机无网络栈），LLM 自由对话只在模拟器。

模拟器（**仅 LLM 对话**需要；真机无网络栈）：

```bash
cd ~/openvela
python3 tools/phywear/sim_console.py cmake_out/vela_goldfish-arm64-v8a-ap-phywear --log /tmp/sim.log --in /tmp/sim.in &
printf 'ai_agent &\n' > /tmp/sim.in      # 模拟器板级没有 rc.sysinit，仍需手动起
printf 'sleep 600\n'  > /tmp/sim.in
printf 'set_llm token-plan-cn.xiaomimimo.com mimo-v2.5-pro <KEY>\n' > /tmp/sim.in
printf 'ask 我想用单摆测重力加速度，请直接帮我把实验页打开并开始测量\n' > /tmp/sim.in
```

- ⚠️ MiMo 的 `tp-` 密钥是 **Token Plan**，必须配 `token-plan-cn.xiaomimimo.com`（用按量付费端点会 401）。
- 拍这段**不要把 Key 露在画面里**：先 `set_llm`，再 `config_show`（显示为 `tp-c****`）。
- 画面角标：**"LLM 对话：goldfish 模拟器（真机无网络栈）"**。

## 二、分段脚本（总长 4:55，含讲稿要点与字幕）

### 片头（0:00 – 0:08，8s）
- 画面：真机 AMOLED 亮屏特写 + 作品名。
- 字幕：`PhyWear · 腕上智慧物理工坊 · 立创黄山派 SF32LB52 · 2026 openvela AI 硬件大赛`

### 第 1 段 · 一句话定位（0:08 – 0:28，20s）
- 讲：把手机 phyphox 的物理实验搬到手表；玩法灵感来自 phyphox（GPL v3，已声明），用 **C + LVGL 独立重实现**。
- 字幕：`玩法来源：phyphox（致谢/GPL）· 实现：C + LVGL（Apache-2.0）`

### 第 2 段 · 真机开机 + 全中文界面（0:28 – 1:05，37s）
- 串口：`phywear lang zh`；画面拍 `SFBL → ABCD → … → NuttShell` 与开机日志（可看到 **`ai_agent` 自启**）。
- 主菜单：8 宫格 → 重点拍 **原始传感器（6 页实时数据）** 与 **声学（2 个可用 + 2 个规划）** 的文案。
- 字幕：`真机实拍 · 全中文 · 6 页原始传感器`

### 第 3 段 · 原始传感器：双视图 + 每轴独立量程（1:05 – 1:35，30s）**（本批新增）**
- 画面：进三轴页（**默认大数字风格**，同环境光页）→ **轻点屏幕切到图线视图** → 再点切回。
- 讲：曲线最初"看不出变化"，根因是**三轴共用一个满量程**（重力把 Z 顶到 2 g，0.12 g 的 Y 只剩 ~3 px）；
  改成**每轴独立量程**后 Y 的摆动到 **±16 px**，底部标注变成每轴一个（如 `+/-1 / 0.20 / 2 g`）。
- 字幕：`轻点切换数值/图线 · 每轴独立量程（Y 轴幅度 3px → 16px）`

### 第 4 段 · 力学与计时：倾角指针盘 + 秒表环形进度（1:35 – 2:05，30s）**（本批新增）**
- 画面：倾斜手表看**指针式角度盘**（13 根刻度逐格点亮）；进秒表页看**环形进度**。
- 讲：两者都避开 `lv_arc`（软件圆弧把帧率从 ~26 拉到 23），用**刻度短线 + 指针**与**分段圆弧**实现；
  秒表页有 1 帧代价（fps 10→9）**如实说明**。
- 字幕：`指针盘（不用 lv_arc）· 秒表环形进度（fps 10→9，如实）`

### 第 5 段 · 单摆测 g（2:05 – 2:40，35s）
- 画面：进「单摆测 g」，摆动一次，展示实时曲线与结果。
- 讲：`g = 4π²L/T²`，实测偏差约 **1.8%**；页面自己 50 Hz 采样解算。
- 字幕：`真机实测：摆测 g 偏差 ≈1.8%`

### 第 6 段 · **主动 + 执行**（2:40 – 3:25，45s）**（本批新增，重点）**
- 画面：**手晃手表 3 秒** → 特写手表 AI 日志出现"检测到持续摆动" → 单摆页**自动打开** →
  出现 `AI: 已自动测重力加速度: g = x.xx m/s^2`；可插一段串口日志证明全链路
  （`检测到持续摆动 → [tools] Executing tool: phywear_run_experiment → ai-coach: AI: …`）。
- 讲三件事（都要说到）：
  1. **它不经对话、自己发起**（赛道要的 proactive + acting）；
  2. 架构关键是**只有 GUI 一路采 I2C**，Agent 只"开页 → 等结果 → 读结果"
     （原先 Agent 自己也 50 Hz 采，两路抢总线导致十几秒卡死，已定位修掉）；
  3. 顺手修掉两个**真崩溃**：Agent 不在时 `velaclaw_ask` 直接断言复位（现在干净拒绝）、工具里 cJSON 双重释放。
- 字幕：`晃表 → 自动跑实验 → 结果上手表 · 修掉两个真崩溃`

### 第 7 段 · 惯性标尺：姿态解算（3:25 – 4:00，35s）**（本批新增）**
- 画面：串口跑 `phywear ahrs 20`，**同时用手转动/倾斜手表**，看输出跟着变；
  可给近景：`roll=+178.12 pitch=+23.63 yaw=+75.63 | accel-tilt r=+178.74 p=+21.94`。
- 讲：Mahony MARG 显式互补滤波（自写实现，未抄参考包）；**磁力计只治偏航**；
  真机实测**AHRS 的 roll/pitch 与加速度计独立解算的倾角一致到 ~0.5°**；
  关掉磁时 yaw 以 ~2°/s 漂（估出的陀螺零偏 −2.18 dps 与漂移率吻合），开磁后**稳定不漂**。
- 字幕：`自写 Mahony MARG · 与加速度计独立解算一致 ~0.5° · 开磁后 yaw 不漂`
- ⚠️ 这一段的数字**只说已实测的**；**精度指标没有转台真值，不要说"厘米级/0.5°精度"**。

### 第 8 段 · 性能与稳定性证据（4:00 – 4:25，25s）
- 画面：`lvgldemo benchmark` 控制台输出（实际数字）→ 叠加真机截图总览。
- 讲：EPIC 硬件加速来自**官方 PR #31/#41/#121**（非本队自研），本队做集成与 UI/算法层优化；
  启动 **5/5** 复位正常；泡机心跳连续。
- 字幕：`EPIC=官方成果，本队集成 · 启动 5/5 · 泡机 0 复位`

### 第 9 段 · 工程深度 + 已知限制 + 归属（4:25 – 4:55，30s）
- 画面：串口跑 `phywear calib` / `phywear ahrs`（自检 rc=0）+ 主机单测 `bash tools/phywear/hosttest_math.sh`。
- 讲 4 个真机问题的定位（**组页点击卡死/启动偶发卡死/麦克风+喇叭互斥/切频率爆音**），
  外加一个"**查到底才发现是构建接线**"的例子：**蓝牙探针** —— 片上控制器与协议栈都在、
  `.config` 里 107 个 BT 项也开着，但固件里只有一个 BT 符号：断在 `UART_BTH4`/`NET_BLUETOOTH` 未开、
  且端口自己的 H4 驱动目录**没有 CMakeLists** → 链接缺符号。**结论 no-go，如实说**。
- 片尾**必须**出现 ≥3 条限制：真机无网络栈；SRAM 已 **93.76%**（累计新增已超"~2 KB"额度约 88 B）；
  ③ 精度无转台真值；蓝牙 no-go；秒表页 fps 10→9。
- 字幕：`已知限制见 docs/01 §已知限制 · 蓝牙结论见 docs/evidence/bt-probe-20260915`

## 四、必须出现 / 必须避免（诚实红线）

**必须出现**

- 「EPIC 硬件加速 = 官方 PR #31/#41/#121，非本队自研」（第 1、8、9 段至少各一次）。
- AI 段落角标：**LLM 对话为模拟器环境；真机无网络栈**。
- 声学段落的如实说明：**响度受板载小喇叭限制、同板声耦合弱**。
- **主动场景已交付**：必须说清"自主检测 → 自主执行"，同时说清**静止时页面可能给出无效 g，我们有有效性门且有残余漏过**。
- ③ 姿态段：只说"与加速度计独立解算一致 ~0.5°"，**不得**宣称精度指标（无转台真值）。
- ④ 蓝牙：**no-go** 及三条断点（可一句话带过）。
- SRAM：**93.76%**，新增已超"~2 KB"额度约 88 B（如实说）。
- 片尾 ≥3 条未实现/限制。

**必须避免**

- ❌ 把 EPIC 说成"本队自研/本队适配"。
- ❌ 把模拟器的 LLM 对话说成真机跑通。
- ❌ 把板子静置时的读数说成"实验结果"。
- ❌ 暗示蓝牙可用（**结论是 no-go**）。
- ❌ 宣称 ③ 的精度指标（"厘米级""0.5° 精度"）—— 只有一致性与稳定性证据。
- ❌ 念稿里没有实测来源的数字（FPS 以现场输出为准）。
- ❌ 画面出现 LLM API Key。
