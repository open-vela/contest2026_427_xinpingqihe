### 当前断点（同一 boot 内对照，决定性证据）
```
phywear bthci   → ✅ [BTHCI] rx (7 B): 04 0e 04 06 03 0c 00   （HCI 链路通）
phywear cap bt  →    dev:0: Sending HCI_RESET → 无回包 → [bt] bt_enable rc=-5 (FAILED)  （-EIO）
```
⇒ 断点**不在 LCPU / 引脚 / 硬件**，而在 **zblue 的 H4 传输层**。

### 三个可疑点（按可疑度）
1. **UART 流控/RTS**（裸探针不用流控；H4 驱动可能要求 CTS）
2. **H4 初始化时序**（LCPU 上电噪声被当坏包 / 缺同步握手）
3. **host 栈重配 UART**（波特率/流控）后与 LCPU 不匹配

### 下一步（按序，勿跳）
1. **打开 H4 层字节级收发日志**（或临时在 H4 驱动收发点加打印）→ 拿到"发了什么 / 收到什么"原文（决定性）
2. 逐个试 Kconfig（流控/波特率）——**每次只改一个**，改动即 编译→烧录→抓串口原文
3. B1 判据 = `[bt] bt_enable rc=0`；随后 **B2** 注册 GATT 服务（参考 `external/zblue/zblue/tests/bluetooth/gatt/src/main.c`）：暴露传感器读数 + 接收命令 + 开广播；**B3 手机连接验证（需人工）**

## 6. 已踩过的坑（别重复）
- **CMake target 名猜错** → `Configuring incomplete`；正确名 `apps_phywear`。
- `grep -c "error"` 会把源码行 `LOG_E("LCDC error code %x")` 算成错误（25 个假阳性 → 白回滚一次）；必须用 `error:`。
- `lv_obj_move_background()` 会把元素压到**不透明底晕之下** → 界面零变化；靠 **sha256** 才发现（"没报错"≠"生效"）。
- 字体子集扫描器只认源码里的**原始 UTF-8 汉字**（`\uXXXX` 不算）；缺字优先**换文案**（零风险），再考虑重跑 `tools/phywear/gen_fonts.sh`。
- LVGL v9：`lv_obj_set_y` 只写样式、`lv_obj_get_y` 读已布局值（新建对象读到陈旧值）⇒ 动画终点必须显式传 base y。
- 抓帧：实时重绘页严格模式必失败；**`/dev/ttyUSB0` 掉线时烧录/串口会全部静默无输出** → 先 `ls /dev/ttyUSB0`。
- 提示符陷阱：`vela>` 是 ai_agent 的 CLI，那里 `phywear` **不是命令**；GUI/探针入口是 `phywear cap <page>` 与 `phywear bthci`。
