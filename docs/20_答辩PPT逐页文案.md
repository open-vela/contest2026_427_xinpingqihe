## 逐页文案

### P01｜痛点：手机实验不趁手
- 要点：手机实验需双手，抬腕不可用（缺数据）
- 要点：开实验打断记录，现象一闪即逝（缺数据）
- 要点：外场无 WiFi，联网实验受限（缺数据）
- 口播：先说痛点。课堂和外场做物理实验，第一反应是掏手机：要解锁、要找 App，现象往往一闪就过。到了没 WiFi 的地方，依赖联网的方案直接歇菜。所以我们想，能不能抬抬手腕就把实验开起来？
- 配图/证据：用自绘的「手机开实验操作链路」示意图 `docs/figures/fig2_dataflow.png`（数据流与链路图）。
- 评委可能追问：痛点有没有用户调研数据支撑，还是你们自己想出来的？

### P02｜方案：腕上物理工坊
- 要点：16 主页 + 传感器 6 子页 + 水平仪 4 子页
- 要点：自研曲线控件，EPIC GPU 硬件 blit
- 要点：蓝牙串口页 + AI 教练页，全中文 UI
- 口播：PhyWear 是一套跑在智能手表上的物理工坊：16 个主页面，加原始传感器 6 子页、水平仪 4 子页，再加蓝牙串口页和 AI 教练页。曲线用自研控件走硬件 blit，全中文界面，抬腕就能看波形、读数据。
- 配图/证据：用 `docs/evidence/ui-v9-20260917/`、`docs/evidence/ui-batch2-20260915/` 的 16 个主页面截图拼图。
- 评委可能追问：16 个主页面里，哪些是真正被高频用到的？

### P03｜架构：三层栈
- 要点：openvela（NuttX）+ LVGL 9.1 全中文
- 要点：pw_scope/pw_graph 走 EPIC 硬件 blit
- 要点：BLE 5.3 承载串口与 PPP，无 WiFi
- 口播：架构分三层：底层是 openvela，也就是 NuttX；中间是 LVGL 9.1 的全中文界面；通信靠 BLE 5.3，既做串口也承载 PPP 联网。曲线控件自己写，把画图交给 EPIC GPU，CPU 省下来跑业务逻辑。
- 配图/证据：用架构图 `docs/figures/fig1_architecture.png`（架构图）。
- 评委可能追问：为什么自研 pw_scope/pw_graph，而不用 LVGL 自带的 chart 控件？

### P04｜硬件：黄山派 SF32LB52
- 要点：SF32LB52 双核 + EPIC GPU，MOD-1-N16R8
- 要点：AMOLED 410×502，VFR 60 Hz 上限
- 要点：16 MB flash / 512 KB SRAM，BLE 5.3
- 口播：硬件选的是立创黄山派 SF32LB52-MOD-1-N16R8：双核加 EPIC GPU，410×502 的 AMOLED，VFR 60 Hz 是面板物理上限。16 MB flash、512 KB SRAM，BLE 5.3 可用；没有 WiFi 网卡，所以联网走 PPP over BLE。
- 配图/证据：用开发板实拍照片 + `docs/07_构建烧录与复现指南.md` 的板卡参数段 + `docs/evidence/realboard-20260912/` 实拍。
- 评委可能追问：为什么不选带 WiFi 网卡的模组？

### P05｜AI-Native 工程方法
- 要点：AI Coding 54 会话 / 15,761 事件 / 12.2 MiB
- 要点：Token 累计 4,649,232,675（两段台账）
- 要点：自建 Skill ×4，DSH + MiMo 双 agent
- 口播：这套东西是 AI-Native 做出来的：AI Coding 日志留了 54 个会话、15,761 个事件、12.2 MiB，Token 累计 46 亿多，两段台账都在。我们自建了 4 个 Skill，由 DSH 和 MiMo 两个 agent 分工协同，人来定方案和验收。
- 配图/证据：用 `logs/XPQHyue/`（54 会话 / 15,761 事件）+ `docs/token_usage/`（Token 台账）+ `docs/evidence/a1-skill-20260913/`。

### P06｜性能工程：39 FPS 来源
- 要点：LVGL benchmark 39 FPS，render 22 ms
- 要点：页面级 48–49 FPS，CPU 约 82%
- 要点：主屏 63 Hz，面板 60 Hz 物理上限
- 口播：39 FPS 是 LVGL 官方 benchmark 的成绩：render 22 毫秒、flush 为 0、CPU 占 83%，轻负载场景 56 到 63 FPS，重负载 15。我们自己的页面跑 48 到 49 FPS。主屏刷新 63 Hz，配置上限 66.7，面板物理上限就是 60 Hz。
- 配图/证据：用 `docs/evidence/lvbench-20260916/` 的 LVGL benchmark 截图与分项数据。
- 评委可能追问：39 FPS 和 48–49 FPS 对不上，是测试口径不同吗？

### P07｜资源占用：SRAM 92%
- 要点：SRAM 483,356 B / 512 KB = 92.19%
- 要点：flash 2,577,592 B / 16 MB = 15.36%
- 要点：69 源文件 / 25,373 行，手写 24,902
- 口播：资源是我们的紧箍咒：SRAM 用了 483,356 字节，占 512 KB 的 92.19%，只剩 7.81% 余量；flash 只用掉 15.36%。代码 69 个源文件、25,373 行，其中手写 24,902 行，另有 1 个生成文件。
- 配图/证据：用 构建末尾 `size -A`/`size` 输出（**缺数据，需补一张截图**）+ `docs/09` §3.5 口径。
- 评委可能追问：SRAM 只剩 7.81%，再加功能怎么办？
