## 二、你问的三件事，逐条给"有/没有"

**① 硬件适配与优化的贡献** —— **有，且是主要得分点**
- 显示：CO5300 AMOLED + **EPIC 硬件加速**；修 **EPIC 栈上触控失效**（官方栈缺陷）
- 触控/传感：FT6146、LSM6DSL、MMC5603、LTR303 驱动打通
- 音频：AUDCODEC DAC/ADC、**MIC 增益**、**喇叭换频爆音**（音量爬坡淡入淡出）
- 时钟：**启动偶发卡死的时钟/晶振建立时序补 2 ms**
- 资源：`g_allsyms` 由 `.data` 改 `const` 进 flash，**−45,952 B SRAM**（蓝牙所需 ~41 KB 因此有余量）
- 蓝牙：LCPU HCI 阶段 A → host 栈 B1/B2/B3，**两处上游级 bug 修复**（H4 跨组 EBADF、`gatt_notify_mc` 漏 handle）
- **新增上游没有的能力**：BLE 文本回环特征（`…a003` 读/写/通知 + 实时 `itv/lat/sto/MTU`）、手表版蓝牙串口页、桌面一键测试 GUI、PPP-over-BLE **端到端打通**、USB CDC-ACM + SLIP 通路（软件就绪，只差一根 USB 线）

**② 难度挑战** —— **有，且三处属"硬骨头"**
- 面板/帧率：CO5300 **VFR=60 Hz 是物理上限**且**无帧率控制寄存器**、TE 无走线 ⇒ 目标"60 以上"**物理不可达**；六个优化假设**实测全部否决**（含"每帧全屏推屏"误判被推翻）
- 蓝牙：两个根因都**不在配置层**，一个在 **NuttX fd 表语义 vs zblue 线程模型**，一个在 **zblue 与上游 Zephyr 的语义漂移**；且第一个的**表象是"控制器不回包"**（极易误判为硬件问题）
- 资源：本板一度**卡在 SRAM 悬崖**（95.98%~96.76%）；真因不是调参而是两处**没有显式配置的栈继承了板级 `CONFIG_DEFAULT_TASK_STACKSIZE=16096`**（NuttX 默认 2 KB）——改成显式 8192 一次省 15,808 B，PPP 两个任务栈再改从堆（PSRAM）上要，最终出货 SRAM **483,356 B（92.19%）**

**③ 工作量** —— **有，可量化**
- 代码：**69 源文件 / 25,373 行**（68 手写 + 1 生成数据块）+ 5 字体 + 大量主机工具（pwshot / pw_accept / pw_bt_b3 / pw_ble_central / pw_bt_gui / pw_h4_notify_decode / pw_hold_conn / pw_xwd2png / make_demo_video / make_report_docx / polish_report_docx）
- 文档：**17 篇 docs** + 41 个证据目录（含 `SHA256SUMS.txt`）+ 技术报告全文 + 官方模板 docx
- 验证：一键验收 18/18、B3 6/6+9/9、GUI 14/14、真机截图 100+ 张、串口原文留档
- AI 日志：**54 会话 / 15,761 事件**；Token **46.5 亿**（逐行解析）
