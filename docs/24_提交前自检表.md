## 7. 提交那一刻

**第 1 步 —— 谁点：队长本人。**
用队长自己的 GitHub 账号登录，亲自点。不许 bot 点、不许 workflow 点、不许 act 模拟点、不许让 AI 代点（仓库规则：最终 merge 必须由人类操作）。点之前把 PR 号 + 当前 PR 页 HEAD sha 发到团队群里留底。

**第 2 步 —— 点什么：只有 "Rebase and merge"。**
PR 页面最底部 → 展开下拉 → **Rebase and merge** → **Confirm rebase and merge**。
只点这一个按钮。"Merge commit"、"Squash and merge" 哪怕是亮的也不许碰（规则：仓库只允许 rebase merge）。点之前再瞄一眼 `cla/signature` 还是绿的（#12），不绿就不点。

**第 3 步 —— 点完看什么：三样。**
① PR 变紫色 **Merged**，commits 列表显示每条 commit 都被 rebase 到 `dev-ai-contest-2026` 上；
② `cla/signature` 保持 success，没有因为 merge 变红；
③ 跑 `git fetch upstream` + `git log -1 upstream/dev-ai-contest-2026 --format='%H %ae'`，输出的 email == `<CLA 邮箱>`，sha 与你刚才发群里的一致。
三样都对，才进 §5 打 zip。**顺序别倒：先 merge 后打 zip，zip 才含最终内容。**

**第 4 步 —— 出问题回滚到哪：merge 前基线。**
- 回滚基线 = 第 1 步发到群里的那个 sha（#33 里也记了）。
- 合错内容 / 合错分支 → 立刻 `git revert` 出反向提交、重开 PR，或回到基线 sha 重新出分支重发 PR。
- **任何情况下不许对 `open-vela/contest2026_427_xinpingqihe` 执行 `git push --force`**，force 只允许作用在自己的 fork 分支上。
- 若 merge 后 `cla/signature` 变红或作者邮箱不对：**不打 zip、不上传**，回 #2 / #3 / #12，修完走新 PR。已上传的先在平台撤回（能撤就撤），撤不了就立刻在群里报备并附 #33 记录。
