效果用在哪 / 为什么关键规则上板可行性
液态 Tab
指示器		 主页与读数页的分页指示 拖动时前后缘节奏不同（先拉长再收拢）；连续快速切换从当前形态接续，最后跟随最后一次选择 ★★★ 纯几何（left/width）+ 圆角，EPIC 友好
中心聚焦
Center-focus		 主页卡片流：8 个板块原本等权、无层级，改成卡片流后"当前项"自然突出 按到容器中心的距离映射缩放/透明度；**视觉焦点 ≠ 业务选择**，不自动改选中项 ★★☆ 真缩放不行（LVGL 子件不随父缩放）→ 上板落成"卡片框宽高 + 邻卡降透明 + 描边/底纹"
手势转场
Gesture transition		 板块页右拖返回；读数页左右拖翻页 位移映射进度、跟手；松手按距离+速度决定完成/取消；保留普通返回按钮；边界不突变 ★★★ 纯几何（当前就是靠 set_pos 动画实现）
共享元素
展开		 点卡片 → 板块页；点迷你图 → 全屏图 源/目标矩形明确对应；关闭回到仍存在的源；中途取消稳定；文字不跟着被拉伸 ★★★ 一个矩形动几何 + 底色，无模糊无阴影
磁吸吸引
Magnetic		 右拖返回的落点提示（过阈值后向"返回"目标吸）；卡片流吸附 进入范围后距离越小吸得越明显、边缘不突跳；拖动中保留控制感；取消不误提交 ★★★ 位移混合（视觉位移 ≠ 输入位移，不改输入事件）
速度形变
Velocity deform		 卡片流快速滑动时卡片轻微拉伸 速度 = 位置差 ÷ 时间差 并平滑；幅度有上限；停手即恢复；正文保持可读、命中区不动 ★★☆ 网页是真 skew/scale；上板只能"卡下强调条按速度伸缩 + 卡片宽度微变"
3D 视差 ✗ 不选：手表没有指针；唯一可用驱动是姿态传感器，而该 Skill 明确不建议默认用传感器驱动运动，且会与横滑抢手势。若以后上"抬腕/倾斜浏览"，再单独评审。
碰撞推挤
Collision		 ✗ 不选：当前界面没有自由浮动元素，加物理引擎属于纯装饰（Skill 也要求"减少元素数量优先于无条件加入物理"）。回弹本身已用在按压与回位。
这版"重构"到底改了什么（不是换色）：
① 导航模型：等权 2×4 宫格 → 横向卡片流（有当前项、有方向、有吸附）；
② 层级：卡片 → 板块页 → 读数页，进出都走共享元素展开，不再是硬切屏；
③ 返回：底部"< >"按钮 → 右拖手势（按钮保留作为备用入口）；
④ 分页：静态圆点 → 液态指示器；
⑤ 图表：点一下切换视图 → 迷你图展开成全屏（下拉收起）。

上板前要确认的三件事： ① 这个卡片流方向对不对（还是你更想要"列表 + 分组"）？ ② 中心聚焦在上板要做降级（缩放→框宽高+透明度），能接受吗？ ③ 速度形变上板只能做成"强调条伸缩"，要还是不要？
